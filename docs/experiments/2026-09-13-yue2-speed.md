# YuE2 Mac inference speed investigation

## Target and controlled comparison

Follow-up to the [Mac feasibility experiment](2026-09-13-yue2-mac.md).
The user judged the original 30-second sample to sound good. That sample's
185-second run spent 91 seconds in acoustic synthesis, 47 in semantic token
generation, 36 in planning including model loading, and 6 in decoding.
Acoustic synthesis is the first optimization target.

## Measured results

On the same M1 Pro / 32 GB Mac and pinned environment, all six runs completed.
The attention comparisons and synthesis timing finished before repository CI
or the separate CLI smoke test started.

| Solver steps | Query tile | Synthesis time | Synthesis speedup | Output comparison |
| --- | ---: | ---: | ---: | --- |
| 32 | 256 | 93.49 s, 93.31 s (mean 93.40 s) | 1.00× | Latents bit-identical to the approved reference |
| 32 | 1024 | 95.33 s, 94.13 s (mean 94.73 s) | 0.99× | Latents bit-identical to the approved reference |
| 16 | 256 | 48.57 s | 1.92× | Changed audio; waveform correlation 0.99883 |
| 8 | 256 | 25.55 s | 3.66× | Changed audio; waveform correlation 0.99709 |

Keep the original 256-row tile: the larger tile is about 1.4% slower in this
small comparison. The 16-step and 8-step trials used that original tile.
Their relative latent RMSEs were 0.0197 and 0.0375 respectively. High waveform
correlation is encouraging but does not replace listening for local artifacts.
All WAVs were read back and verified as finite, non-silent 48 kHz stereo,
1,439,936 frames (29.999 seconds). All 32-step waveforms matched the original
up to audio-file quantization.

The first decoder call took 7.41 seconds including loading; subsequent calls
took 2.57–2.65 seconds. These decoder timings are separate from the synthesis
comparison and demonstrate why model lifetime matters in interactive use.

Replacing only the original run's 91.44-second synthesis stage gives estimated
whole-request times of **142 seconds at 16 steps** and **119 seconds at 8
steps**, versus 185 seconds originally: approximately **23% and 36% less
time**. These are estimates, not measured fresh end-to-end 30-second runs.
Planning and semantic generation are unchanged. Each reduced-step setting
was measured once; the repeated ABBA comparison applies to attention tiling.

The practical next option is reduced-step synthesis with listening validation.
The standalone probe exposes `--steps 16` and `--steps 8`; its default remains
32. No app setting or production generation default was changed.

## Benchmark method

`Scripts/benchmark-yue2-mac.py` reuses the original score, semantic tokens,
seed, and weight hashes. It verifies the saved artifacts before running. Only
the acoustic attention query tile or midpoint solver step count changes.
No prompt, lyric, or semantic-generation differences confound the comparison.

The original attention code defaults to 256 query rows on MPS. This experiment
also tries 1024, preserving every visible key and the causal mask. It warms up
both shapes, then runs 32-step synthesis in ABBA order (256, 1024, 1024, 256).
Finally it tries 16 and 8 steps with the faster measured tile. Model weights
remain resident across synthesis trials. Decoder work happens afterward and
is timed separately. There is no quantization or automatic CPU fallback.

Latent equality is tested against the original approved sample. For changes
that alter the output, latent error and waveform correlation are diagnostics,
not measures of musical quality. Each trial writes its own WAV for listening.
Fewer steps are an experimental quality/speed trade-off; YuE2's 32-step
checkpoint must not be described as an 8-step distilled model.

## Which H3ddle optimizations transfer?

| Existing technique | YuE2 applicability |
| --- | --- |
| Attention scheduling | Testable through the upstream `query_chunk_size` argument; larger tiles reduce the number of attention calls while retaining full attention. Equality and timing must both be measured. |
| Fewer denoiser evaluations | Testable through `steps`; 32 midpoint steps evaluate velocity 64 times. The reduced-step outputs need listening review. This is not the same algorithm as H3's cached-core reuse. |
| Fixed conditioning/KV caching | Already implemented by YuE2's `CachedNAR`: the AR prefix KV is built once per acoustic chunk and reused through all solver steps. AR token generation also has a KV cache. |
| Resident model reuse | Fits H3ddle's existing persistent engine approach. Reuse the pipeline and verified weights across jobs. YuE2 moves the transformer to CPU for VAE decoding, so retaining the Python object alone does not eliminate every later device transfer. |
| Fused projections, normalization/RoPE, SwiGLU | Candidates for a native adapter, not existing switches in the PyTorch pipeline. H3ddle has related kernels, but YuE2 has separate AR/NAR weights, 16 query heads and 8 KV heads, and its own layouts and numerical boundaries. Validate stage-level parity before measuring gains. |
| INT8/input-major weights | Requires YuE2-specific conversion and a compatible native quantized execution path. H3's measured INT8/layout gains do not establish YuE2 gains or quality. YuE2's bundled FP8 path is CUDA-specific. |
| Cached core, skipped blocks, token reduction, sparse attention | Possible research experiments, but H3's schedules and error thresholds have not been validated for YuE2. Audio quality could change, so they are not recommended defaults from this experiment. |
| M5 TensorOps kernels | Not applicable to the tested M1 Pro. |

Relevant local implementations are `Engine/Sources/SA3/sa3_dit_gpu.c`
(fixed prompt KV and constant conditioning),
`Engine/Sources/H3Native/H3NativeBridge.c` (resident model caches),
and `Engine/Vendor/h3.c/h3_gpu.h` (normalization, RoPE, attention and SwiGLU).

PyTorch also documents `PYTORCH_MPS_PREFER_METAL` for matmul routing and
`PYTORCH_MPS_FAST_MATH` for different kernel arithmetic. Both were unset in
this experiment. Neither should be advertised as faster without a separate
controlled test. See the [PyTorch 2.10 MPS environment documentation](https://docs.pytorch.org/docs/2.10/mps_environment_variables.html).

## Reproduction

Use the pinned environment and weights from the feasibility note. Keep all
weights and generated artifacts outside the repository. If needed, first
produce the 30-second reference with `probe-yue2-mac.py --cot full
--max-tokens 750` and a fresh output directory. Then:

```sh
"$probe_root/venv/bin/python" -u Scripts/benchmark-yue2-mac.py \
  --model "$probe_root/model" --vae "$probe_root/vae" \
  --reference "$probe_root/run-full-750/artifacts" \
  --output "$probe_root/benchmark-1"
```

The output directory must not already exist. `benchmark.json` records all
timings, effective reference settings, checkpoint hashes, latent differences,
audio statistics, and any failing stage. Synthesis timing includes acoustic
prefix preparation, the solver, synchronization and the latent CPU transfer;
it excludes initial model loading, warmup and audio decoding. Memory values
are observations after each trial, not measured peaks. ABBA reduces warmup
and time-order bias but is still a small single-machine experiment.

## Validation

All six synthesis trials and decoded-file checks passed. A separate end-to-end
25-token smoke test using `probe-yue2-mac.py --steps 16` also passed and recorded
`generation.ode_steps=16` and the explicit override in its saved configuration.
That short test ran alongside CI, so its runtime is not used for any speedup
claim. Both scripts passed syntax and CLI checks.

`Scripts/ci.sh` was rerun after the timed benchmark. It passed the public
boundary and earlier checks, then both attempts at `H3ddleEngineClientTests`
exited during “Cancelling generation keeps the helper process alive”; the
final status was 1. It did not reach the remaining suites or app build. This
experiment changes standalone Python probes and documentation only; the
engine-client implementation and tests are unchanged.
