# AuK on Apple Silicon: feasibility experiment

## Scope

**Result: both AuK-Flash instruction TTS and AuK Base reference-audio editing
ran end to end on this 32 GiB M1 Pro using unmodified upstream PyTorch/MPS
code.** This establishes local execution, not audio-quality or shipping
readiness. Memory use is high and the required Qwen encoder has a research
licence rather than MIT.

Evaluate the released AuK inference implementation on the local M1 Pro before
adding an application backend. The app, model catalog, and engine protocol are
unchanged. Source, environments, weights, logs, and audio live outside the
repository. The optional harness is `Scripts/probe-auk-mac.py`.

## Revisions and environment

- Apple M1 Pro, 32 GiB unified memory, macOS 26.6.2, arm64.
- Python 3.11.15; torch/torchaudio 2.7.1; torchvision 0.22.1;
  transformers 4.57.6; torchdiffeq 0.2.5; qwen-omni-utils 0.0.9.
- AuK source: `0dfd4d39015078351217b09a40e263355aaa646b`.
- Base: `790742b71a4430120daf2b2099192abae449eb9f`.
- Flash: `575b92f0895f75180bf2cbd35f2e176c5732b8ed`.
- Qwen2.5-Omni-3B: `f75b40e3da2003cdd6e1829b1f420ca70797c34e`.
- Explicit `device="mps"`; automatic unsupported-operator CPU fallback disabled.
- MPS recommended maximum: 26,800,603,136 bytes. This is not measured usage.

The installed package's 27 Python source files matched the pinned source
byte-for-byte before inference. The default upstream loader selects CUDA or
CPU, so explicit MPS selection is necessary. It converts the combined
conditioner/DiT to FP32; its `dtype` argument only controls CUDA autocast.
The harness sets MPS high/low allocation watermarks to 1.0/0.9, retaining a
hard cap at the device recommendation. An initial invocation set only the
high watermark and failed before loading because PyTorch's default low
watermark (1.4) exceeded it; the harness now sets both consistently.

## Checkpoint inventory

Each AuK checkpoint is 6,122,209,092 bytes; the shared VAE is 637,322,604 bytes.
The three Qwen shards total 11,972,663,208 bytes. One variant plus the full
Qwen snapshot's weight shards and VAE totals 18,732,194,904 bytes (17.45 GiB),
excluding tokenizer/configuration files and the Python environment. Both
variants with a shared VAE/Qwen total 24,854,403,996 bytes (23.15 GiB).

Qwen's snapshot also includes unused vision, Talker, and token-to-waveform
weights. A production conversion should extract only the required text/audio
Thinker tensors, after compatibility validation. Disk sizes are not runtime
memory estimates.

## Component probes

- Real Metal access and core AuK imports passed.
- A randomly initialized, full-width transformer with one double-stream and
  one single-stream block passed finite-output checks with zero and 150
  reference frames. This checks operator support, not generated speech quality
  or the full 30-block model.
- The released VAE encoded and decoded a three-second synthetic sine signal
  on MPS. Loading took 2.56 seconds, encoding 2.87 seconds, and encoding plus
  decoding 7.06 seconds. The decoder returned 72,000 finite mono samples at
  24 kHz. MPS driver allocation at the end was 2,327,363,584 bytes.

## End-to-end results

The unmodified released pipeline produced a valid three-second instruction-TTS
WAV on MPS. It used the released four-step schedule with CFG disabled. Base
then processed that recording with a whisper-conversion instruction using
32 steps and default CFG 2.0. Both WAVs were finite, non-silent, unclipped,
and successfully read back from disk. The whisper effect and preservation of
the requested words/voice were not judged by listening or ASR.

| Measurement | Flash instruction TTS | Base audio edit |
| --- | ---: | ---: |
| Load | 107.48 s | 96.87 s |
| Generation, including conditioning and decode | 24.60 s | 84.57 s |
| Reference VAE encoding | Not used | 1.37 s |
| Conditioning | 6.12 s | 38.66 s |
| Decode | 1.46 s | 1.09 s |
| Total probe elapsed | 137.14 s | 185.20 s |
| Output | 3.000 s, 24 kHz mono | 3.000 s, 24 kHz mono |
| Highest observed MPS allocated memory | 21.96 GiB | 22.09 GiB |
| Highest observed MPS driver memory | 22.60 GiB | 23.65 GiB |
| RMS / peak amplitude | 0.09999 / 0.45174 | 0.11210 / 0.54436 |
| Samples at clipping bounds | 0% | 0% |

Load and generation timings exclude environment installation and downloads.
Generation includes instrumentation/synchronization overhead. These are single
runs in fresh processes with potentially warm filesystem/shader caches, not
repeated performance benchmarks. System swap was in use during loading; its
total cannot be attributed entirely to this process on a shared development
Mac. No listening-based or transcription-based quality judgment was made.

All downloaded LFS weight hashes matched the pinned Hub manifests, including
Base, Flash, VAE, all three Qwen shards, and the Qwen tokenizer JSON.

## Repository validation

The harness passed syntax and CLI checks. `Scripts/ci.sh` ran the boundary
checks, Python utilities, native C checks and the core Swift suites, then
`H3ddleEngineClientTests` timed out after 120 seconds on both attempts
(exit 124). The same target timeout was recorded by the preceding YuE2
experiment. CI did not reach later suites or the final app build; this is
not a passing full-CI result. Other application work was occurring in the
shared checkout and was not modified by this experiment.

## Distribution constraint

AuK's own code and weights are MIT. Its required Qwen2.5-Omni-3B encoder is
under the Qwen Research License, which defines noncommercial as research or
evaluation and says commercial users must request a separate licence. This
experiment is evaluation; the complete released stack must not be presented
as unrestricted MIT software. Using an external download or porting its
weights to Metal does not remove that dependency's terms. Substituting another
Qwen model is not a validated drop-in change to learned AuK conditioning.

## Integration assessment

The follow-up [speed investigation](2026-09-13-auk-speed.md) tests reduced
precision, residency, caching, and solver counts. Its mixed loader reduces
the full FP32 footprint measured here; consult those results before choosing
the native implementation's precision and memory policy. The authoritative
[native integration plan](../designs/2026-09-13-auk-native.md) incorporates
these results and requires C/Metal inference with no Python runtime.

The successful Flash run establishes local MPS inference feasibility without
an operator compatibility patch. It does not establish a native C/Metal port
or a production-ready backend. The existing helper
process boundary is suitable, but the production backend still needs:

1. A licensing path for the required encoder before general commercial use.
2. Reduced model residency and load-time duplication. Keep one variant active;
   use BF16 Qwen with FP32 DiT/VAE as the native candidate identified by the
   follow-up tests, then validate native numerical agreement and performance.
3. Native implementations of the text/audio conditioner, hidden-layer fusion,
   30-block DiT and flow sampler, and the VAE encoder/decoder using Metal.
   Python remains exclusively in external development/reference tools.
4. All-task audio evaluation, longer inputs, repeated requests, cancellation,
   crash recovery, model manifests, and fake-provider protocol/UI tests.

Do not advertise 16 GiB support or a 32 GiB production minimum from these
measurements. Flash's four steps do not materially shrink the loaded model.
The source/reference path is shared by edits, but successful execution alone
does not certify correct edits or separation quality. A native port should
preserve the released Flash time grid and Base guidance before optimizing.

## Reproduction

Install the pinned upstream source and dependencies into an isolated Python
environment, and use `hf download --revision` for the revisions above. Keep
configuration and VAE next to each AuK checkpoint. Provide the complete Qwen
snapshot separately. Run with normal Metal access; a sandbox can hide MPS.

```sh
python3 Scripts/run-with-timeout.py 1200 \
  "$auk_probe_root/venv/bin/python" -u Scripts/probe-auk-mac.py \
  --model "$auk_probe_root/flash" --qwen "$auk_probe_root/qwen" \
  --output "$auk_probe_root/flash-tts" --seconds 3

python3 Scripts/run-with-timeout.py 1200 \
  "$auk_probe_root/venv/bin/python" -u Scripts/probe-auk-mac.py \
  --model "$auk_probe_root/base" --qwen "$auk_probe_root/qwen" \
  --audio "$auk_probe_root/flash-tts/audio.wav" \
  --instruction 'Convert this speech into a soft whisper while preserving the speaker and content.' \
  --output "$auk_probe_root/base-edit" --seconds 3
```

The harness refuses existing output directories. It saves stage timings,
memory observations, exceptions, dependency versions, and WAV validation.
Memory observations are snapshots, not a continuous peak. Process peak RSS
and MPS allocations overlap and must not be added. A finite, non-silent WAV
does not establish intelligibility, speaker similarity, language coverage,
CUDA parity, or quality across all 16 tasks.
