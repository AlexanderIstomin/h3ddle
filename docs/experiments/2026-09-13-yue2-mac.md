# YuE2 on Apple Silicon: feasibility experiment

## Scope

**Result: YuE2 runs on this Mac through the unmodified released PyTorch/MPS
pipeline.** Both short end-to-end probes passed, including a run with generated
melody/chord planning. A compatibility port was not needed for these samples.

Test the released YuE2 inference package on a real Mac before adding a model
choice to H3ddle. This is an optional, standalone experiment: the app, model
catalog, engine protocol, and default music provider are unchanged.

The public quick start describes Linux/CUDA, but inspection of the 0.1.5
wheel found explicit MPS device selection, CPU sampling for MPS, grouped-query
attention adaptation, and a PyTorch eager path without CUDA graphs. An Apple
Silicon port should not be assumed necessary before testing this path.

## Test environment

- Apple M1 Pro, 10 CPU cores, 32 GB unified memory.
- macOS 26.6.2, arm64, Python 3.11.15.
- `yue2-infer==0.1.5`, `torch==2.10.0`, `transformers==4.57.6`,
  `huggingface-hub==0.36.2`, `numpy==2.2.6`, `soundfile==0.13.1`.
- `device=mps`, `backend=torch-eager`, no quantization, no source patches.
  All 14 installed `yue2/*.py` files were compared byte-for-byte with the wheel.
- MPS reported 26,800,603,136 bytes of recommended maximum memory. This is
  a device recommendation, not the experiment's measured memory consumption.

## Results

Measured on 2026-09-13. Each run used a fresh process; OS file and GPU shader
caches may have been warm. Times include local verification and loading but
exclude downloading and environment installation. These are two feasibility
samples, not a repeated performance benchmark.

| Measurement | Direct generation | Melody/chord planning |
| --- | ---: | ---: |
| Planning mode | `off` | `full` |
| Semantic token limit | 250 | 750 |
| Generated audio | 9.999 s | 29.999 s |
| Total probe elapsed | 84.46 s | 185.23 s |
| Resolve and verify | 5.17 s | 4.71 s |
| Plan stage, including first model load if needed | 0.00 s | 35.58 s |
| Semantic stage, including first model load if needed | 45.25 s | 46.58 s |
| Acoustic synthesis | 27.20 s | 91.44 s |
| Decoder loading and decoding | 4.96 s | 5.97 s |
| Highest observed MPS allocated memory | 6.83 GiB | 7.21 GiB |
| Highest observed MPS driver memory | 7.29 GiB | 11.99 GiB |
| Audio RMS amplitude | 0.0708 | 0.1088 |
| Audio peak amplitude | 0.6598 | 0.7391 |
| Samples at clipping bounds | 0% | 0% |

Total elapsed also includes Python startup within the harness, intermediate
artifact writes, and validation. Each output was read back as finite,
non-silent, 48 kHz stereo WAV with distinct left/right channels. All upstream
result artifact checksums verified. No listening-based quality judgment was
made.

The full planner emitted 615 tokens including its end token and saved an ABC
score with vocal/instrumental parts and chord symbols. Both audio runs reached
their requested token caps, so `semantic.truncated=true`; neither demonstrates
natural song completion. The full run used upstream CFG 1.0, while direct
generation used upstream CFG 1.01 with two conditioning branches.

The 30-second run spent most of its time in acoustic synthesis. A subsequent
integration/performance investigation should measure longer songs and repeated
requests before promising a memory minimum or extrapolating generation times.

## Reproduction

Use an external directory for the environment, weights, logs, and generated
audio. Do not put these in the repository. The commands below use `uv` and the
Hugging Face `hf` CLI. GPU execution needs normal Metal device access; a
sandbox can report `torch.backends.mps.is_available() == False` on an otherwise
supported Mac. The probe fails instead of silently switching to CPU.

```sh
probe_root=$(mktemp -d /private/tmp/h3ddle-yue2.XXXXXX)
export HF_HOME="$probe_root/hf"
export UV_CACHE_DIR="$probe_root/uv-cache"

hf download m-a-p/YuE2-3B yue2_infer-0.1.5-py3-none-any.whl \
  --revision 29b3558dd46954a0cd9021dc76d5c91864a0f1c7 \
  --local-dir "$probe_root/upstream"
uv venv --python 3.11 "$probe_root/venv"
uv pip install --python "$probe_root/venv/bin/python" \
  "$probe_root/upstream/yue2_infer-0.1.5-py3-none-any.whl"

hf download m-a-p/YuE2-3B \
  --revision 29b3558dd46954a0cd9021dc76d5c91864a0f1c7 \
  --include '*.safetensors' --include '*.json' --include '*.tiktoken' \
  --include LICENSE --include THIRD_PARTY_NOTICES.md --include 'licenses/*' \
  --local-dir "$probe_root/model"
hf download m-a-p/YuE2-Vae \
  --revision 9a94e1d0ea9f8087e98f77fa88df4a4068104d2a \
  --include '*.safetensors' --include '*.json' \
  --include LICENSE --include THIRD_PARTY_NOTICES.md --include 'licenses/*' \
  --local-dir "$probe_root/vae"

"$probe_root/venv/bin/python" -u Scripts/probe-yue2-mac.py \
  --model "$probe_root/model" --vae "$probe_root/vae" \
  --output "$probe_root/run-250" --max-tokens 250
```

Wheel SHA-256:
`8801e2c0d969db02df78d2994150b4ccd86077d87c24fdb8509b1f6f31462641`.
The pipeline verifies the model and decoder against their supplied weight
manifests. Together the two weight files occupy 7,791,954,360 bytes.

The probe writes `probe.json`, `audio.wav`, intermediate semantic tokens and
latents, plus upstream result artifacts containing prompts, configuration,
weight hashes, audio, and timings. It refuses to overwrite an existing output
directory. Failure reports retain the failing stage and traceback.

The default test deliberately caps generation at 250 semantic tokens and
disables score planning (`cot=off`). It keeps upstream BF16 transformer,
FP32 decoder, CFG 1.01, and 32-step midpoint synthesis defaults. Automatic
unsupported-operator CPU fallback is disabled. Upstream's intentional CPU
sampling, noise creation, weight staging, and audio transfers still occur.

Use a fresh output directory and `--cot full` to exercise score planning;
increase `--max-tokens` for a longer audio sample. The cooperative timeout
is checked during token generation and synthesis; it cannot interrupt a
blocked model load, GPU call, or decoder call.

The follow-up [speed investigation](2026-09-13-yue2-speed.md) compares attention
tiles and solver counts using the approved sample. `--steps` is available for
explicit experiments; its default remains 32. Reducing it changes the audio
and is recorded in the effective generation configuration.

## Evaluation boundaries

A passing probe means all requested stages ran and produced finite, nonempty,
non-silent stereo audio. It does not certify musical quality, lyric accuracy,
CUDA numerical equivalence, full-song stability, or production suitability.
Token-capped results are explicitly marked truncated. MPS memory observations
are snapshots, not a continuous peak measurement; process peak RSS is recorded
separately and must not be added to MPS memory as if they were disjoint.

H3ddle integration would still need model-based audio engine selection,
persisted lyrics and planning options, out-of-process lifecycle/cancellation,
fake-provider coverage, and length/memory testing. The prototype does not
establish a native C/Metal implementation or a shipping Python distribution.

Both weight repositories advertise CC BY-NC 4.0; the inference wheel also
ships license and third-party notices. Preserve those terms in any subsequent
integration. This experiment adds no upstream implementation or model weights
to H3ddle.

## Repository validation

The probe passed Python syntax/CLI checks. Running it without visible Metal
access failed explicitly at the environment stage and saved the expected
diagnostic report instead of generating on CPU.

`Scripts/ci.sh` was run. The public-boundary check, Python utility tests,
native C checks, and earlier Swift suites passed, but
`H3ddleEngineClientTests` did not finish: its first attempt exited while
running the cancellation test, and the script's automatic retry exceeded
120 seconds (exit 124). CI therefore did not reach the remaining suites or
the final app build. The initial sandboxed attempt also lacked Swift cache
access; the reported test timeout is from the subsequent unsandboxed run.
No application, engine, or test-suite source was changed by this experiment.
