# YuE2 native C/Metal engine

The native backend replaces the Python worker in the app. It uses h3.c's Metal
buffer, BF16 matrix, normalization, RoPE, attention, and MPSGraph convolution
operations. An Objective-C adapter implements checkpoint-native byte BPE with
Foundation's Unicode handling. The C pipeline performs score planning, semantic
sampling, acoustic flow matching and tiled 48 kHz stereo decoding. The helper
writes PCM24 WAV output and supports cancellation through the engine protocol.

No interpreter, Python package or extra subprocess runs during app inference.
The first native version releases its model allocations after each request.

## Pinned numerical reference

Public `m-a-p/YuE2-3B`, revision
`29b3558dd46954a0cd9021dc76d5c91864a0f1c7`, inference wheel 0.1.5;
`m-a-p/YuE2-Vae`, revision `9a94e1d0ea9f8087e98f77fa88df4a4068104d2a`.
See [upstream](https://huggingface.co/m-a-p/YuE2-3B) and the source attribution
in `Engine/Sources/YuE2/NOTICE.md`. Model weights remain external to the repo.

The transformer has 28 layers, width 2048, 16 query heads, eight KV heads, head
dimension 128, FFN width 6144, and separate AR/NAR projections and MLPs. The
native attention extension exposes all acoustic positions plus their cached AR
prefix. Existing causal attention retains its original mask.

The midpoint solver evaluates velocity twice per displayed step. The UI's
8/16/32 values preserve this meaning. The decoder consumes 64-channel, 25 Hz
latents, uses strides 6, 5, 4, 4, 2, 2, and produces `1920*T - 64` stereo samples.
Native VAE tiling uses 128-frame cores with 16-frame halos and crops cores
without crossfading, preserving the natural output length.

## Validation on M1 Pro, 32 GB

The native harness ran with `MTL_DEBUG_LAYER=1`. These relative L2 errors compare
fixed tensors, not independently sampled songs:

| Check | Result |
| --- | --- |
| Style/instruction token IDs plus Unicode, combining marks and special-looking text | Exact |
| First transformer block | 0.00549 |
| Final AR logits | 0.00185 |
| Final AR logits with cached decode | 0.00205 |
| NAR velocity | 0.02091 |
| Final latents, 8 / 16 / 32 steps | 0.01032 / 0.01087 / 0.01158 |
| Decoder waveform from 160 fixed latent frames | 0.00000115 |

The waveform has 307136 samples per channel, crosses a native tile boundary,
and has maximum absolute error approximately 0.00000108. A separate seam check
prevents a local discontinuity from hiding in a global error measure. These
results establish numerical agreement within tested tolerances, not bitwise
identity or a broad perceptual-quality evaluation.

A complete ten-second request through the native JSONL helper succeeded with
Metal API validation enabled and PATH restricted to `/usr/bin:/bin`. It produced
9.998667 seconds of stereo audio in 155.9 seconds, including model loading and
full score planning. Reported process footprint reached about 9.0 GB at the
recorded phase boundaries and fell to about 472 MB after completion. This is one
cold validation run, not a controlled speed comparison against Python.

The rebuilt app's bundled helper also completed a one-second request through
`EngineGenerationProvider` with Metal validation enabled (105.6 s, including
full planning and cold load). `Scripts/ci.sh` passed, and the isolated native UI
test passed for step selection, queue/lyrics restoration and Reset. The app
bundle contains no Python worker, and app/engine sources have no YuE2 interpreter
launch path. The ten-second PCM24 sample has RMS 0.0738, peak 0.4438 and no clipped
samples; listening quality still merits user evaluation.

The production-path test found a rotation table larger than the helper thread's
stack. Its storage now belongs to the model's heap workspace; the corrected run
completed successfully.

## Reproducing parity

Development tools only; Python is used to export the reference, not to execute
the native engine. Supply a saved sample's `artifacts` directory from the
feasibility probe:

```sh
python3 Scripts/export-yue2-native-reference.py \
  --package "$YUE2_PACKAGE" --sample "$YUE2_SAMPLE/artifacts" --output "$YUE2_PARITY"
python3 Scripts/build-yue2-check.py --output /tmp/yue2-check
MTL_DEBUG_LAYER=1 /tmp/yue2-check "$YUE2_PACKAGE" \
  Engine/Vendor/h3.c/h3_shaders.metal "$YUE2_PARITY"
python3 Scripts/check-yue2-native-reference.py "$YUE2_PARITY"
```

The exporter requires the pinned reference environment. Fixtures and audio must
stay outside the repository. The checker asserts explicit tolerances and writes
`parity.json`. Normal CI checks validation and protocol behavior without weights.

## Limits and follow-up optimization

The app now offers 1–360 seconds (9000 semantic frames) and optional lyrics.
Blank lyrics add instrumental/no-vocals style conditioning. Requests may end early.
Attention falls back to a 256-key tiled online softmax when scores exceed Metal’s
threadgroup storage. Both causal and noncausal paths were compared with a CPU
oracle at 257, 7168, 9001 and 24576 keys with Metal validation enabled; maximum
absolute output error was below 0.000244. Scratch and KV buffers grow only when
needed. Acoustic chunks follow `(24576 - prefix_tokens - 3) / 2`, preserving the
full-song noise draw; the decoder retains its bounded tiles.
Long text is rejected before sampling when planning plus semantic tokens exceed
the model context. Six-minute full-song quality and latency have not been measured.

The native SplitMix64/Box–Muller sampler is request-local. It does not promise
PyTorch RNG equivalence, even with the same seed. BF16 fused operations and
reduction order also cause small numerical differences. Validate fixed inputs
before judging free-running sampled outputs.

Model weights remain BF16 and VAE arithmetic FP32. Further speed work should
measure command-buffer batching, prefill attention and model reuse. Quantization
and H3-specific approximations require separate quality tests. C alone does not
guarantee faster inference.

## Premature completion display and acoustic attention fix

A cancelled 120-second, 8-step instrumental request had stored overall progress
2999/3000. YuE2 had been classified as a single-phase audio engine, so semantic
token progress filled the monotonic overall bar before acoustic synthesis began.
The previous acoustic implementation also submitted all 28 transformer layers
before reporting work or checking cancellation, allowing a long silent interval.

The app now uses a YuE2-specific stage profile. Token generation ends at 30%,
audio-context preparation at 35%, synthesis at 97%, and decoding/saving at 99%.
Only the completed event reaches 100%. Remaining time is extrapolated from
completed acoustic work, never from semantic token pace. Original acoustic chunks
aggregate their step/layer counters. Every completed acoustic transformer layer
submits and synchronizes its GPU work before progress and cancellation checks.

Noncausal grouped-query attention now uses native Apple MPSGraph SDPA; the scalar
Metal path remains selectable with H3_YUE2_REFERENCE_ATTENTION=1. The CPU attention
oracle passed through 24576 keys. All frozen tokenizer, AR, 8/16/32 acoustic and
VAE checks passed (acoustic latent relative L2 at most 0.010708).

The same cancelled request settings completed in 669.70 seconds, producing a
119.998667-second, 48 kHz stereo PCM24 WAV. Planning took 95.54 seconds, music-token
generation 272.33 seconds, audio-context preparation 76.72 seconds, acoustic
synthesis 188.05 seconds, and decoding 7.23 seconds; loading, other preparation
and saving account for the rest. There were 464 synthesis progress events with
no gap exceeding 0.574 seconds. The recorded real events passed through the actual
Swift progress tracker: monotonic progress, token stage at or below 30%, active
work below 100%, and terminal completion at 100%.

A focused 1100-frame velocity check measured 5.564 seconds for the first optimized
evaluation and 8.338 seconds for the scalar reference, with relative L2 0.016695
between their outputs. This is a same-input kernel check, not an end-to-end
speedup claim. Maximum-context allocation and cancellation after acoustic layer 1
also passed with Metal validation enabled. Full Scripts/ci.sh passed; the optional
recorded-progress test passed separately (12 tracker tests total).

## Fixed-work Python comparison and cache reuse

The development benchmark replays the same 698-token prefix, 750 codec frames,
CPU-generated FP32 noise and decoder input in both implementations. Python uses
the pinned yue2-infer 0.1.5 / PyTorch 2.10 MPS environment, with automatic CPU
fallback disabled. Native weights and activations remain BF16; VAE arithmetic
remains FP32. These measurements use normal Metal execution rather than the
validation layer used for the earlier production replay.

| Stage | Python seconds | Native seconds |
| --- | ---: | ---: |
| Second prefix prefill | 2.499 | 3.254 |
| Second 128-token teacher-forced decode | 10.805 | 7.058 |
| Cold acoustic conditioning + 8 steps | 30.523 | 41.111 |
| Cold acoustic conditioning + 16 steps | 62.740 | 64.012 |
| Cold acoustic conditioning + 32 steps | 109.914 | 118.212 |
| Decode fixed 750-frame latent | 7.331 | 2.393 |

The native cache is explicitly reset before each synthesis trial. These stages
are not a full-song benchmark and must not be summed into an end-to-end claim:
the token trial decodes only 128 tokens. Background load and thermal conditions
also vary between sequential runs. All three native latent outputs passed the
existing 0.02 relative-L2 bound (0.009588, 0.009194, 0.017579); decoded fixed-input
audio relative L2 was 0.00000130.

Smaller attention query tiles were rejected: interleaved warmed 750-frame
velocities measured about 2.19 seconds for full queries and 2.51–2.73 seconds for
256-row tiles. An interleaved matrix-layout comparison measured means of 1.629
seconds for rank 3 and 1.615 seconds for rank 2. The latter is a small change,
not evidence of a substantial speedup.

The helper now records the token identity and extent of its valid AR cache.
Stage transitions reuse only the matching prefix, recomputing a final position
when logits are required. A diverging suffix is recomputed; replacing KV buffers
invalidates the cache. The initial allocation includes the acoustic context
budget so entering synthesis does not discard the just-generated token cache.
NAR writes begin after the cached AR prefix. This removes repeated conditioning
work without skipping transformer layers or changing the solver.

Developer commands, using fixtures outside the repository:

```sh
"$YUE2_REFERENCE_PYTHON" -I Scripts/benchmark-yue2-native-python.py \
  --package "$YUE2_PACKAGE" --sample "$YUE2_SAMPLE" --output "$YUE2_BENCH"
python3 Scripts/build-yue2-check.py --output /tmp/yue2-check
/tmp/yue2-check --benchmark "$YUE2_PACKAGE" \
  Engine/Vendor/h3.c/h3_shaders.metal "$YUE2_BENCH" > "$YUE2_BENCH/native.jsonl"
python3 Scripts/check-yue2-benchmark.py "$YUE2_BENCH" "$YUE2_BENCH/native.jsonl"
/tmp/yue2-check --cache "$YUE2_PACKAGE" \
  Engine/Vendor/h3.c/h3_shaders.metal "$YUE2_PARITY"
```

The cache check uses the short frozen parity fixture and exercises reuse after
NAR writes, then compares a diverging suffix against a cold recomputation.
It passed with Metal validation enabled: repeated conditioning was bit-identical,
and the changed suffix had velocity relative L2 0.011770 against recomputation.

For a complete fixed-token compute comparison, add `--replay` to the Python
command and use `--replay-benchmark` in the native harness. This executes every
score and music-token forward pass, with synchronization at each token, and
preserves each backend's production cache behavior at stage transitions. The
checker reports measured planning + semantic + synthesis + decoding time for
each step budget. Sampling and initial model/tokenizer loading are excluded from
those totals; decoding includes decoder loading in both backends. The separate
production-protocol replay measures the real end-to-end cost. Neither backend
samples shorter token sequences in this test.

The complete 750-frame fixed-token replay passed at every step budget:

| Steps | Python measured stage total (s) | Native measured stage total (s) | Native time reduction |
| --- | ---: | ---: | ---: |
| 8 | 145.639 | 103.265 | 29.1% |
| 16 | 170.777 | 130.854 | 23.4% |
| 32 | 237.192 | 188.348 | 20.6% |

Planning measured 38.271 seconds in Python and 26.614 natively; the complete
music-token stage measured 61.842 and 40.986 seconds respectively. Native
synthesis alone was slightly slower at 8 and 16 steps (32.485 versus 30.987,
and 60.073 versus 56.125 seconds), so the speed claim is about the complete
measured workload, not every operation. At 32 steps synthesis measured 117.568
seconds natively versus 122.540 in Python. Decoder loading and execution measured
3.180 versus 14.539 seconds.

Reusing the sequentially generated AR cache also passed the original numerical
bounds: latent relative L2 was 0.010355, 0.009680 and 0.017591 for 8/16/32 steps
(limit 0.02). Decoded fixed-input audio relative L2 was 0.00000130 (limit 0.0001).
No precision, layer-count or solver changes were used to obtain these results.
`check-yue2-benchmark.py --require-faster` passed for this replay; that optional
gate requires native total time at or below Python at every step budget, in
addition to the numerical checks. It rejects the shorter microbenchmark mode.

## Two-minute production replay after cache reuse

On the M1 Pro, the original 120-second maximum, 8-step request was run sequentially
in the pinned Python pipeline and the updated native production JSONL helper.
Both used normal Metal execution, full chord/melody planning, seed 65859680,
empty lyrics and the same style text including the instrumental suffix. Both
generated 3000 semantic frames and 119.998667 seconds of stereo audio.

| Measurement | Python | Native |
| --- | ---: | ---: |
| End-to-end seconds | 681.673 | 579.441 |
| Music-token generation seconds | 365.935 | 266.913 |
| Acoustic synthesis seconds | 198.055 including conditioning | 189.285 plus 0.144 conditioning |
| Decoding seconds | 36.799 including decoder load | 9.485 |

Native used 15.0% less end-to-end time for these request settings. This is not an
identical-song comparison: their RNGs differ, and native planned 2063 ABC tokens
versus Python's 1167. The fixed-token benchmark above separately controls the
amount of work. Native score-to-semantic context preparation took 0.081 seconds,
and semantic-to-acoustic preparation took 0.144 seconds, versus 11.76 and 76.72
seconds in the earlier native replay before cache reuse.

The completed native PCM24 WAV is 48 kHz stereo, RMS 0.145893, peak 0.895990.
Peak physical footprint was 9,807,944,496 bytes. These signal checks verify
nonempty output and duration, not perceptual quality.

Full-project validation also exposed a helper shutdown hang following
cancellation. A sampled test process was stuck in Foundation's `waitUntilExit`
inside `EngineSession.abandon`, after the helper had exited. Shutdown now uses
bounded polling after its existing termination/SIGKILL escalation instead of an
unbounded Foundation wait. The cancellation regression passed three consecutive
runs, asserting return within three seconds and verifying that the helper PID
no longer exists.

Final `Scripts/ci.sh` passed without a timeout or retry after both preemption and
shutdown waits were corrected. The recorded 120-second native event trace passed
through the actual Swift progress tracker; the complete engine-client suite
passed in 1.638 seconds. CI rebuilt and verified the signed debug app and bundled
helper. UI tests were compiled but not rerun in this backend-only performance
pass; the earlier step/lyrics/duration UI checks are recorded above.
