# AuK Mac speed investigation

Follow-up to the [AuK feasibility experiment](2026-09-13-auk-mac.md), on the
same M1 Pro / 32 GiB Mac and pinned torch 2.7.1 environment. This experiment
changes only standalone probes and documentation. It does not change an app
backend, model package, generation default, or upstream source file.

**Result:** the useful mixed configuration is BF16 Qwen with FP32 DiT and
VAE. It reduced mean warmed Base edit time from 102.02 to 24.26 seconds;
combining it with 16 Base steps reduced that to 11.35 seconds. These are
small-sample, single-Mac feasibility measurements with changed audio requiring
review. BF16 DiT was slower, and FP16 DiT produced nonfinite latents.

Recommended integration candidates are persistent models, exact-input caches,
the BF16-Qwen/FP32-DiT loader, and a separately reviewed 16-step Base preview
preset. Retain the 32-step Base option and the released Flash schedule. The
licensing and all-task quality constraints from the feasibility note remain.

The [native integration plan](../designs/2026-09-13-auk-native.md) makes these
implementation candidates explicit. These timings measure PyTorch/MPS, not
the proposed native C/Metal engine; native speedups require fresh benchmarks.

## Completed resident/cache baseline

| Base, 32 steps, FP32 | Generation time | Output comparison |
| --- | ---: | --- |
| Resident model, uncached inputs | 90.07 s, 113.96 s | Identical latents and WAV samples |
| Resident model, cached inputs | 21.23 s, 21.10 s | Identical latents and WAV samples |

These four requests share the same three-second reference and instruction.
Their mean times are 102.02 and 21.17 seconds: approximately 4.82x faster for
cached repeats, with substantial variability in the uncached timings. This
does not accelerate a changed instruction or source audio. Cold loading took
112.76 seconds before warmup and is excluded from the table.

The first full-residency conditioner sweep recorded FP32 at 92.48 seconds,
then BF16 at 3.30 and 0.56 seconds. BF16 features had relative RMSE 0.02751
and correlation 0.99962 against FP32. Its final BF16-to-FP32 conversion hit
the Metal cap: 24.87 GiB allocated against 24.96 GiB allowed while requesting
another 1.16 GiB. That ABBA sweep is incomplete and is not a reliable paired
speedup estimate. The completed resident/cache trials above remain valid.

The continuation stages dtype conversions on CPU, outside timed regions,
and keeps the inactive DiT off Metal throughout the conditioner comparison.
It reuses the saved FP32 baseline outputs through `--stages-only --comparison`
and reconstructs fixed conditioning with one short preparation call. It
retains the original allocation cap rather than disabling memory protection.

## Completed stage comparisons

With the inactive denoiser off Metal, conditioner ABBA timings were
**5.746 / 0.534 / 0.539 / 4.236 seconds** (FP32/BF16/BF16/FP32). Mean BF16
time was 0.536 seconds versus 4.991 seconds for FP32, approximately 9.31x
faster in this setup. Restored FP32 features were bit-identical; BF16 feature
relative RMSE was 0.02751 and correlation 0.99962. Observed allocated memory
after conditioning was about 16.38 GiB for FP32 and 8.86 GiB for BF16.

| Fixed FP32 conditioning, Qwen released | Sampling time | Latent relative RMSE | Waveform correlation |
| --- | ---: | ---: | ---: |
| FP32 DiT, 32 steps, first A | 26.946 s | 0 | 1 |
| BF16 DiT, 32 steps, first B | 41.347 s | 0.00708 | 0.999964 |
| BF16 DiT, 32 steps, second B | 24.295 s | 0.00708 | 0.999964 |
| FP32 DiT, 32 steps, final A | 19.040 s | 0 | 1 |
| FP32 DiT, 16 steps | 9.608 s | 0.01723 | 0.999516 |
| FP32 DiT, 8 steps | 4.830 s | 0.05796 | 0.995730 |

BF16 denoising was slower in both adjacent A/B pairs: its mean was 32.82
seconds versus 22.99 seconds for FP32. It saved weight memory but did not
provide a denoising speedup. Absolute timings drifted substantially, so these
are feasibility results rather than a precise throughput ranking. The final
warm FP32 baseline gives approximately 1.98x/3.94x sampling speedups for
16/8 steps; the reduced-step trials were measured once each.

All complete stage trials produced finite, non-silent, unclipped audio.
Changing both conditioner and DiT to BF16 produced latent relative RMSE
0.00876 and waveform correlation 0.999949 against the full FP32 reference.
That combined cached run took 25.23 seconds including decoding.

## Mixed-loader end-to-end check

Keeping Qwen BF16 and DiT FP32 avoided the large whole-model FP32 expansion.
Fresh-process loading took **23.74 seconds** rather than 112.76 seconds for
the initial full-residency baseline. These are process-cold, not disk-cache-
cold measurements. The first complete generation took 29.90 seconds; two
subsequent uncached generations took **24.06 and 24.47 seconds**. Cached
generation took 22.32 seconds.

Compared with the 102.02-second mean of the resident FP32 baseline, the mixed
loader's 24.26-second mean is approximately **4.20x faster** for this edit.
Maximum observed driver allocation across those trials was **16.50 GiB**.
Qwen weights occupied 8,069,560,320 bytes (BF16), DiT 6,122,154,240 bytes
(FP32), and VAE 637,188,212 bytes (FP32).

All four outputs matched one another, with latent relative RMSE 0.00511 and
waveform correlation 0.999988 against the full FP32 baseline. They were
unclipped and had the expected three-second, 24 kHz mono shape.

An additional fresh-process BF16-Qwen/FP16-DiT trial failed on its first
generation with `Generated latent contains NaN/Inf`. No valid audio or speedup
was claimed for FP16. Keeping the integrator and VAE FP32 was insufficient to
make this denoiser precision stable; the tested recommendation retains FP32
denoiser weights/compute.

The combined mixed-loader/16-step Base configuration also passed four complete
requests. Loading took 24.04 seconds; the first generation took 17.90 seconds.
Two warmed uncached requests took **11.38 and 11.31 seconds** (mean 11.35),
and a cached repeat took 10.46 seconds. The warmed mean is approximately
**8.99x faster** than the original resident FP32/32-step mean, on this one
short edit. Highest observed driver allocation was **16.46 GiB**.

Output relative latent RMSE was 0.01790 and waveform correlation was 0.999468
against the original FP32/32-step reference. All WAVs were finite, non-silent,
unclipped and three seconds long. This validates combined runtime execution,
not perceptual equivalence or quality on longer clips and other tasks.

## Flash end-to-end check

The same BF16-Qwen/FP32-DiT loader completed four Flash requests, retaining
the released four-step grid and CFG 0. Loading took 33.22 seconds; the first
generation took 24.43 seconds. Subsequent uncached requests took **10.76 and
6.65 seconds**, and the cached repeat took 5.66 seconds. Highest observed
driver allocation was **15.56 GiB**.

All outputs were finite, non-silent, unclipped, three-second 24 kHz mono WAVs.
Waveform correlation against the original FP32 feasibility WAV was **0.98876**,
with relative waveform RMSE 0.15348. This differs more than the Base edit and
needs listening review. No original Flash latent reference was saved, so no
latent comparison is claimed. There is no controlled resident FP32 Flash
baseline in this speed experiment; do not calculate a warmed speedup by
dividing the previous first-generation time by these warmed times.

## Method

`Scripts/benchmark-auk-mac.py` verifies the downloaded weights against the
pinned Hub manifests, replays a passed feasibility request, and writes trial
WAVs, normalized target latents, timings, memory observations, and numerical
comparisons. Base reuses the three-second generated speech as input to a
whisper-conversion instruction. Flash uses the original instruction-TTS task.
Neither sample has a listening-based quality approval.
The controlled stage sweeps use Base; Flash is tested through the compact
end-to-end path against its original feasibility WAV.

The initial full run is warmup. Two subsequent FP32 runs measure resident
model reuse. Two more cache the processor output, Qwen conditioning, and
reference VAE encoding, with the same inputs and seed. Cache reuse is valid
only when all conditioning inputs are identical; it is not a speedup for a
new script or different edit instruction. A production cache must include
model revision, precision, instruction, reference content, preprocessing, and
any stochastic reference-encoding seed in its identity.

Qwen conditioning is tested in FP32/BF16/BF16/FP32 order, with warmup after
each dtype selection. Qwen was originally loaded from BF16 and expanded to
FP32, so restoring its weights from BF16 does not lose checkpoint precision.
Floating buffers, including rotary frequencies, retain their original values
and dtypes throughout the comparisons.
The inactive DiT is staged on CPU for all four conditioning measurements;
dtype changes also stage through CPU to avoid simultaneous old/new Metal
allocations. These transfers are outside the timed regions.

After conditioning comparisons, Qwen is released for both denoiser precision
variants. The exact same cached FP32 conditioning, reference latents, and
noise seed feed an FP32/BF16/BF16/FP32 denoiser comparison. FP32 denoiser
weights are reloaded from the checkpoint after BF16; expanding rounded BF16
weights back to FP32 would not restore the baseline. Changes in residency
must be distinguished from the effect of dtype alone.

Base additionally runs 16 and 8 Euler steps in FP32, preserving CFG 2.0 and
the upstream sway formula. These change its sampling schedule and require
audio review. Flash retains its released four-step grid with CFG disabled;
it is never treated as a configurable-step Base checkpoint.

The combined test uses BF16 Qwen conditioning and BF16 denoiser weights.
The VAE, layer-fusion parameters, and ODE integration remain FP32. BF16
forwards use MPS autocast, and denoiser output returns to FP32 for integration.
No INT8/INT4 quantization or automatic unsupported-operator CPU fallback is
enabled. Fast-math and alternate matmul routing are recorded but not enabled.

The optional `--compact-smoke` mode intercepts the upstream loader's one
whole-model FP32 expansion at runtime. It keeps Qwen in its loaded BF16 dtype
and selects denoiser precision before checkpoint loading/device transfer
(`--dit-precision fp32`, the experimentally selected default),
while preserving floating buffers. It restores the original method after
construction and runs real uncached requests plus a cached repeat. This is
an experimental loader adapter, not unmodified upstream execution.

## Measurement boundaries

All timings synchronize MPS. Model loading, warmups, conversions, checkpoint
verification, audio-file writes, and numerical comparison are excluded from
the timed generation regions. Generation includes input preparation,
conditioning, sampling, latent capture/transfer, decoding, and synchronization.
The nested sampler timing includes conditioning; subtract the separately
reported conditioning time when comparing denoising alone.

Memory is observed after stages/trials, not continuously sampled peak usage.
The Mac is a shared development machine, so system swap cannot be assigned
entirely to AuK. Timed experiments run sequentially, with no benchmark-owned
CI or second model job running alongside them. ABBA reduces ordering bias but
does not establish statistical significance from a single machine/sample.

Waveform correlation and relative latent RMSE are numerical diagnostics, not
speech-quality metrics. Equal lengths and finite non-silent audio do not
establish intelligibility, accurate edits, or unchanged speaker identity.
Every changed-output recommendation remains subject to listening and broader
task evaluation. The encoder licensing constraint from the feasibility note
also remains in force.

## Relationship to existing H3ddle and YuE2 optimizations

| Technique | AuK assessment |
| --- | --- |
| Persistent helper/model | Directly applicable; measured separately from cold loading. |
| Cached complete conditioning | Valid for identical instruction/reference/preprocessing/seed; tested explicitly. |
| Reduced denoiser evaluations | Tested for Base at 16/8 steps; Flash keeps its released four steps. |
| Reduced weight precision | Tested on Qwen and DiT independently, then together; not equivalent to INT8 quantization. |
| CPU offload | Upstream's switch is CUDA-only. Moving a model to CPU on unified memory is not the same as freeing it; the sampling test actually releases unused Qwen. |
| Per-layer prompt KV cache | Cannot assume YuE2's optimization transfers. AuK jointly updates text/reference and target states inside the denoiser; later-layer keys/values can depend on the current noisy target. |
| Attention query tiles | AuK uses full PyTorch SDPA rather than YuE2's exposed query-chunk control. A different attention schedule needs a separate parity/performance test. |
| Fused normalization/RoPE/SwiGLU, input-major INT8 weights | Plausible native-backend work, but not measured by this Python experiment. Existing H3 gains do not establish AuK gains. |
| Skipped layers, sparse attention, cached denoiser core | Not validated for AuK; these can alter edits or speech quality. |
| M5 TensorOps | Not applicable to the tested M1 Pro. |

## Reproduction

Use the external environment, checkpoint folders, manifests, and successful
probe outputs from the feasibility experiment. Output folders must be new.

```sh
python3 Scripts/run-with-timeout.py 2400 \
  "$auk_probe_root/venv/bin/python" -u Scripts/benchmark-auk-mac.py \
  --model "$auk_probe_root/base" --qwen "$auk_probe_root/qwen" \
  --reference "$auk_probe_root/base-edit/probe.json" \
  --audio "$auk_probe_root/flash-tts/audio.wav" \
  --output "$auk_probe_root/base-speed"
```

For Flash, select its model folder and TTS probe JSON and omit `--audio`.
For the compact loader, add `--compact-smoke` and
`--comparison "$auk_probe_root/base-speed/resident-fp32-1"`, with a new output
folder. The comparison argument is a trial prefix, without `.wav` or `.npy`.
Use `--base-steps 16` or `8` only in compact-smoke mode to test reduced Base
steps in complete requests. Flash still uses its released grid. When only a
reference WAV exists, use `--comparison-wav`; latent comparison is then
explicitly unavailable rather than compared with an invented reference.

## Validation

The benchmark passed syntax, CLI, and whitespace checks. Successful trials
verified finite, non-silent output and exact float-WAV sample round-trips.
FP32 cache and restored-FP32 trials reproduced the reference latents exactly.
The mixed-loader Base outputs were also compared directly as decoded sample
arrays and were identical across its four repeats. WAV file hashes can
differ because their container metadata differs.

`Scripts/ci.sh` ran after all timed GPU work and **passed (exit 0)**, including
the engine-client suite that timed out in earlier experiments, the other
Swift suites, helper checks and app/test-bundle build/signing. UI test
execution remained skipped by the default setting. Other work in the shared
checkout was preserved; this experiment did not change the application or
production inference defaults.
